# 对外时效 API v1

所有 API 只读，返回 JSON，统一路径 `/api/v1`。生产环境与前端同源。接口从数据库中只读取指定公司、已发布、有效、非取消的海运记录，不包含后台增删改、批量发布、原始采集内容或内部备注。

## 接口

| 方法与路径                        | 作用                                                           |
| --------------------------------- | -------------------------------------------------------------- |
| `GET /health/live`                | 进程存活                                                       |
| `GET /health/ready`               | 验证数据库连接及两个有效视图的访问权限                         |
| `GET /api/v1/meta`                | 数据来源、默认月份、可用月份、港口和渠道筛选项                 |
| `GET /api/v1/overview`            | 三个视角总览、六个月趋势、航线/仓库排行、柜子分布              |
| `GET /api/v1/entities/:dimension` | 当前筛选下可加入对比的候选项，支持分页搜索                     |
| `GET /api/v1/compare/:dimension`  | 最多四项对比、独立指标样本、共同样本分段、历史趋势、分布和排行 |

`dimension` 为 `containers`、`routes`、`warehouses`。前后端共用的完整响应类型位于 `shared/contracts.ts`。

## 通用筛选

| 参数          | 默认                       | 规则                                                       |
| ------------- | -------------------------- | ---------------------------------------------------------- |
| `month`       | 服务器上海时区上一个自然月 | `YYYY-MM`，不接受未来月份；按实际开船月分组                |
| `origin`      | `all`                      | 精确起运港名称，从 meta 获取                               |
| `destination` | `all`                      | 精确目的港名称                                             |
| `channel`     | `all`                      | 公司渠道；独立于具体航线                                   |
| `inspection`  | `all`                      | `all` / `yes` / `no`                                       |
| `search`      | 空字符串                   | 柜号子串，最多 80 字符，大小写不敏感；SQL 通配符按字面匹配 |

未知参数、重复标量参数、非法年月和不合法取值返回 400。前端通过 URLSearchParams 编码中文。

总览额外支持 `statistic=mean|p90`，控制主力航线趋势，其他总览卡片保持原来的均值口径。

对比与候选项支持 `metric=total|sea|tail`。柜次/航线的 total 为开船到拆柜，tail 为到港到拆柜；仓库的 total 为开船到实际送仓，tail 为拆柜到实际送仓。sea 均为开船到实际到港。

对比支持 `ids=id1,id2`，最多 4 个且不得重复。ID 从候选项接口取得，不根据仓库名称或柜号自行拼装。未传 ids 时选择当前指标均值最快的三项；`ids=` 明确表示不选择任何项。没有匹配的公开样本时保留空统计，不返回私有记录的名称或存在性。

候选项支持 `q`（名称/说明搜索）、`page`（从 1 开始）、`pageSize`（默认 20，最大 50）。响应为 `{ items, page, pageSize, total }`；按均值、名称和 ID 稳定排序。

示例：

```sh
curl 'http://127.0.0.1:3001/api/v1/overview?month=2026-10'
curl 'http://127.0.0.1:3001/api/v1/entities/routes?month=2026-10&pageSize=20'
curl 'http://127.0.0.1:3001/api/v1/compare/warehouses?month=2026-10&metric=tail'
```

## 统计约定

- `Summary` 返回 `count, mean, p90, min, max`；空样本为 `count=0`，其余为 `null`。
- P90 为排序后位置 `(n-1)*0.9` 的线性插值，不等于服务承诺。
- 每项指标独立使用其有效端点；中间节点缺失不抹掉有效总时效。
- 分段堆叠图只使用所有分段都有效的共同样本，并单独返回 `stages.count`。不能把来自不同分母的均值直接相加。
- 柜号可重复使用，柜次以 shipment ID 区分；航线按船司和 service_name 组合分组。缺少 service_name 的柜次不会被推断到某条航线。
- 仓库按实际送仓批次加权；必须符合 `amazon_warehouse` 范围，不包括快递、FBM、整柜和私人地址。
- 当前月及近期月份仍存在在途样本；总览同时返回有效柜次总数和总时效样本数。
- 所有历史比较按开船月份分组。月份缺失返回 null，图表保留断点。
- 日期字段和指标受既有 `has_metric_issue`、`is_valid_data` 规则限制；未来的实际节点不用于已完成时效。
- 直方图使用左闭右开区间，末档含上界；最多 60 档，极端值进入最后一个 `N+` 档，不被丢弃。
- 排行在页面中最多展示 8 项，完整候选项通过分页接口获取。

## 数据与访问边界

PostgreSQL 模式使用 `valid_container_metrics` 和 `valid_amazon_delivery_metrics`，再强制校验 `is_published`、固定 `SOURCE_TENANT`、有效开船日期和海运状态。公司范围由服务器配置，客户端不能改写。原始记录不会整行序列化到响应。

查询使用参数绑定，文本搜索转义 `%`、`_` 和反斜杠。同一响应在只读、可重复读事务中获得一致快照。单次查询最多处理 50,000 条柜次及 50,000 条送仓样本；超过上限返回 422，不悄悄截断。未来规模扩大时应迁移为数据库分组聚合，而不是提高上限。

`DATA_SOURCE=demo` 是显式演示模式，不与真实数据库混合；数据库连接失败绝不自动退回演示数据。浏览器收到 API 故障会显示错误和重试。所有 API 返回 `Cache-Control: no-store`，前端查询在窗口聚焦时重新获取；已显示的快照不会在无请求时自动获知后台撤回。

## 错误

```json
{
  "error": {
    "code": "INVALID_QUERY",
    "message": "筛选参数格式不正确，请检查月份、指标与对比项。",
    "requestId": "req-1"
  }
}
```

- 400 `INVALID_QUERY`：参数不合法。
- 404 `NOT_FOUND`：未知资源或未提供的写入接口。
- 422 `QUERY_TOO_LARGE`：需缩小查询范围。
- 429 `RATE_LIMITED`：每客户端 IP 默认每分钟 120 次。
- 503 `DATA_UNAVAILABLE`：数据库或数据服务暂时不可用。

响应和日志不暴露数据库连接串、密码、原始 SQL 错误。默认不信任客户端转发的 IP 头；若未来增加反向代理，应在确认代理地址后配置精确的信任范围。
